> **一句話介紹**：專為 AI Agent 設計的專欄排版技能。能將長篇專欄、新聞圖片或長文，自動重構為**「手機優先滑動卡片（重點速讀）＋ 典雅直式全文閱讀」**的極致雙模式響應式網頁，並自動部署至 GitHub Pages！

---

## 🌟 為什麼需要這個技能？（解決的核心痛點）

傳統新聞與長篇專欄在數位化轉發給客戶或社群分享時，常常面臨兩難：
1. **傳統長文網頁**：文字過於密集，手機讀者注意力難以維持，容易直接跳出。
2. **傳統投影片（PPT/Reveal.js）**：字體在手機端等比縮小變成「螞蟻字」，上下留有巨大黑邊，操作極不順手。
3. **過多花俏小工具**：加了過多互動試算器或懸浮按鈕，反而干擾專欄本身的觀點傳遞。

本技能採用**「雙模式無縫切換」**架構：
* 📱 **重點速讀模式（Slide Card View）**：以 Swiper.js 渲染 5～6 頁大字重點卡片，手機滑動流暢，大螢幕自動居中如 App 般雅緻。
* 📜 **全文閱讀模式（Full Article Mode）**：100% 完整收錄原專欄每一字每一句，提供長輩與深度讀者最舒服的閱讀體驗。

## 📐 核心架構與排版規範

### 1. 📱 重點速讀卡片黃金 6 頁結構

| 頁碼 | 頁面主題 | 內容要素 |
|:---:|:---|:---|
| **Slide 1** | **封面與案例背景** | 出處期數徽章、大主標題（`Noto Serif TC` 亮白/金黃）、副標、真實案例背景框。 |
| **Slide 2** | **核心盲點提煉** | 標籤「核心盲點 01」、大字問題核心、3 大條列關鍵分析點、作者提醒警示卡。 |
| **Slide 3** | **數據懸殊對比** | 標籤「數據對比 02」、3 條橫向數據大字對比卡（數字 `28px~36px`）、利差/趨勢小結。 |
| **Slide 4** | **市場反常/黑天鵝** | 標籤「市場現象 03」、反常局勢卡片（搭配 emoji 如 🇨🇳 🇯🇵 ⚠️）、局勢引言。 |
| **Slide 5** | **行動指南/戰術建議** | 標籤「行動指南 04」、三大編號行動方針卡（`1. 安全第一` `2. 分流配置` `3. 雙邊防禦`）。 |
| **Slide 6** | **專家金句與總結** | 標籤「專家金句」、紅色高對比引言卡（標註作者職稱）、3 點精華要點條列。 |

### 2. 📜 全文閱讀模式
* **字級與行高**：基礎字體 `18px ~ 19.5px`，行距 `1.9`，首行縮排 `2em`。
* **重點標記**：重要觀點以粗體紅字或下劃線標記，中段附上「關鍵數據摘要框」。

## 🕳️ 踩坑紀錄與避坑指南（Lessons Learned）

在開發本排版技能時，我們總結了以下 **5 大常見地雷與最佳解法**：

### ❌ 坑 1：傳統 PPT 引擎在手機端縮放成螞蟻字
* **問題**：Reveal.js 等投影片框架會將 960px 畫布強制等比縮小至手機 390px 寬度，文字縮小 60% 完全無法閱讀。
* **解法**：全面棄用傳統 PPT 引擎，改用 **Swiper.js 原生行動端標準像素渲染**，手機直屏大字排版（`17px ~ 20px`）。

### ❌ 坑 2：iOS Safari 底部 100vh 遮擋與按鈕被切掉
* **問題**：使用 `100vh` 時，Safari 底部動態導覽列會吃掉下方內容，導致「下一頁」按鈕被遮蔽或消失。
* **解法**：採用 `height: calc(100vh - 62px)` 與 `overflow: hidden`，配合彈性 Flex Column 結構，讓底部控制列自然吸附在可視安全區域內。

### ❌ 坑 3：功能過載（Feature Creep）破壞閱讀節奏
* **問題**：在專欄網頁中硬塞試算小工具、多重浮水印或傳統雙頁演講模式，導致 UI 雜亂，讀者無法專注文章核心。
* **解法**：**極簡克制**，嚴格只保留「重點速讀」與「全文閱讀」兩個核心模式，導覽列僅保留必要標籤與切換 Tab。

### ❌ 坑 4：桌機螢幕過寬導致卡片拉伸變形
* **問題**：手機優先卡片在 27 吋或寬螢幕上全螢幕拉伸，文字過長失去卡片節奏。
* **解法**：在桌機端自動加上 `max-w-lg`（約 512px 寬度）與精緻外邊框，在桌機中央展現如精美原生 App 的聚焦視覺。

### ❌ 坑 5：瀏覽器強快取導致更新看不見
* **問題**：LINE 或 Safari 內嵌瀏覽器對靜態頁面快取強烈，GitHub Pages 更新後手機依然看到舊版。
* **解法**：`<head>` 內強制宣告 `Cache-Control: no-cache, no-store, must-revalidate`。

## 📦 自動化發布 SOP

當 Agent 接收到指令後，會自動執行以下流程：
1. **讀取全文**：精確 OCR 或讀取專欄每一字每一句。
2. **提煉與生成 `index.html`**：依 6 頁規範生成速讀卡片與全文閱讀。
3. **Git 初始化與推送**：建立 GitHub 公開倉庫並推送至 `main`。
4. **開啟 GitHub Pages**：透過 `gh api` 啟用 Pages，並自動在瀏覽器中開啟驗證。
